# Live CEX Opportunity Research Workflow Design

## Outcome

The repository will provide one real-data, read-only Opportunity workflow for
`UNI/USDT`. One command will collect synchronized public order books from
Binance and Bybit, retain the exact source bytes and hashes, calculate both
directions at the existing USD notional grid, publish a complete Current
Opportunity bundle, and optionally open the normal read-only Opportunity page.

The result is a market-research estimate. It is useful even when every net
edge is negative. It is never an order instruction, never a fill promise, and
never an `executable_candidate` because the workflow has no authenticated fee
or inventory evidence.

## Scope

This increment includes:

- token and pair: `UNI/USDT`;
- venues: Binance and Bybit;
- directions: Binance buy / Bybit sell and Bybit buy / Binance sell;
- requested notionals: USD 1,000, 5,000, 10,000, 50,000, and 100,000;
- one bounded synchronized collection window;
- public order-book and public instrument-rule evidence;
- exact common-quantity level walking using the retained books;
- optional, reviewed public taker-fee upper bounds;
- immutable core and complete-bundle publication;
- the existing `/api/markets/opportunities` API and `/opportunities` page;
- a manual refresh command and an optional loopback-only server.

This increment excludes:

- API keys, account data, balances, wallets, signing, orders, or transfers;
- authenticated account fee tiers or inventory claims;
- arbitrary token, venue, endpoint, proxy, RPC, or URL input;
- OKX quantity finalization until its quote-cash precision is independently
  evidenced; its public book collector remains available outside this workflow;
- automatic scheduling, public internet deployment, CEX-DEX routes, and DEX-DEX
  routes.

## Why Binance and Bybit

The tracked token configuration currently names Binance and OKX. Both venues
already have public book adapters, but the existing strict quantity contract
also needs base and quote amount lattices. OKX's public `tickSz` is a price
lattice, not proof of the quote-cash settlement increment. Substituting it
would create false precision.

Binance and Bybit already have retained, validated instrument-rule adapters
that produce the existing `route_market_rules_source/v1` contract. The first
complete real workflow therefore uses Binance and Bybit. This is a deliberate
evidence decision, not a synthetic fallback. OKX is not silently relabeled as
fully supported.

## Trust and safety boundary

### Fixed public network allowlist

The workflow may issue only HTTPS GET requests generated by existing adapters
for these exact hosts and endpoint families:

| Purpose | Host and endpoint |
| --- | --- |
| Binance order book | `data-api.binance.vision/api/v3/depth` |
| Binance instrument rules | `api.binance.com/api/v3/exchangeInfo` |
| Bybit order book | `api.bybit.com/v5/market/orderbook` |
| Bybit instrument rules | `api.bybit.com/v5/market/instruments-info` |

The command exposes no URL, host, proxy, redirect, shell command, credential,
or arbitrary request option. Existing bounded response sizes, deadline-aware
timeouts, retry limits, rate-limit handling, and raw-response retention remain
authoritative. Redirects must not broaden the fixed-host boundary.

### Local writes

The command may write only below the explicitly supplied local `--data-dir`.
It writes raw evidence, immutable route core bundles, immutable complete route
bundles, and their atomic latest pointers. It does not modify account data,
browser state, or third-party systems.

### Claim boundary

Every published row from this workflow must satisfy all of the following:

- `opportunity_class` is `research_estimate` or `unavailable`;
- `strict_eligible` is `false`;
- `strict_ready_for_publication` is `false`;
- `publication_attestation_sha256` is `null`;
- missing public fee bounds remain unavailable rather than zero;
- missing or stale book/rule evidence suppresses economic values rather than
  reusing old or synthetic data.

The existing authenticated CEX finalizer remains unchanged and separate. A
public research option must not be added to its default path.

## Architecture

```text
fixed UNI/USDT research universe
  -> existing bounded route cohort collector
       -> Binance book + rules, raw bytes retained
       -> Bybit book + rules, raw bytes retained
       -> typed source manifest + synchronized route timing
  -> existing immutable route core publication
  -> public-research input builder
       -> replay retained book/rule/USD evidence
       -> derive one exact common UNI quantity per route/notional
       -> walk both books for that same quantity
       -> attach public fee upper-bound components when available
       -> mark inventory/rebalancing evidence unavailable
  -> existing complete-bundle publication and cold reload validation
  -> existing Current Opportunity API and page
```

The production route Shadow authority is not weakened or enabled. That
authority represents a separate systemd/storage promotion contract. A manual
public research refresh calls the existing bounded collector directly and
publishes only research-class complete bundles through the normal immutable
publisher.

## Fixed research universe

A new pure builder returns `route_universe/v1` with:

- `candidate_source_generation`: SHA-256 of the canonical fixed configuration;
- two selected CEX legs, `cex:binance:UNI/USDT` and
  `cex:bybit:UNI/USDT`;
- both directional `prepositioned_inventory` route identities;
- the repository's existing five requested notionals;
- no claimed historical volume; reference-volume fields are null;
- a fixed descriptive selection window identifying this as a point-in-time
  public research collection.

The generation reader rebuilds this same universe before collection and at the
existing collector checkpoints. Any code/config drift fails the run before
publication.

## Collection contract

One refresh uses the existing `collect_route_cohort()` implementation with:

- deadline: 60 seconds;
- target observation time: command start in UTC;
- at most four workers, with existing per-venue limits;
- a generated immutable snapshot/run identifier;
- raw root `<data-dir>/raw/route-cohort`;
- both venue books requested within the same cohort;
- actual venue timestamps when supplied, otherwise the measured response time;
- route skew limit: the existing 60 seconds;
- route age limit at API projection: the existing 120 seconds.

A leg failure is retained with its stable reason. The command may publish a
complete bundle containing unavailable scenarios so that the UI explains the
failure; it must not substitute cached books or a fixture.

## Public research calculation

### Common quantity

For each direction and notional, the builder replays the retained typed market
rules and USD conversion. It calls the existing `common_target_quantity()` to
choose one UNI quantity aligned to both venues' base-unit and lot-size
lattices. The buy and sell book walkers receive that identical target.

### Book cash flow

When a current public fee bound exists, the quantity quote uses that same
conservative maximum rate, received-asset basis, rounding rule, and public
fee-record hash. The matching cost component carries the identical rate and
hash, so the existing opportunity validator recognizes the fee as already
reflected in the leg cash flow and does not subtract it twice.

When no current public fee bound exists, the book can still be replayed with an
explicit zero-rate mechanics object solely to expose gross price/slippage. The
fee component remains `unavailable`, scenario cost completeness is incomplete,
and research net is null. Zero is never presented as the venue fee.

### Public taker-fee bounds

The existing `collect_cex_fee_snapshot(..., allow_public_estimate=True)` path
is used. A tracked schedule row must contain one unambiguous venue/instrument/
side match, a checked time, a finite validity window, an HTTPS official source,
and a minimum/maximum interval. Calculation uses the maximum taker-fee bps.

The resulting component is `bounded_estimate`, is never strict eligible, and
is reflected exactly once in the research net edge. If no current exact row
matches, the component is `unavailable`; the workflow still publishes
source-backed gross book results, but research net remains unavailable.

### Route mode and inventory

No account inventory is inspected. `classify_route_mode_evidence(route,
now=...)` supplies an ineligible research-mode projection. The
`rebalancing_or_transfer` component is unavailable, with a stable reason that
pre-positioned balances were not evidenced. It is never marked
`not_applicable`.

### Direction and ranking

Both directions are calculated independently. A negative edge is retained.
The UI's existing filters and sort order operate on the published research
fields. No minimum-profit filter is introduced.

## Evidence and publication

The existing collector and publisher remain the authority for:

- raw response SHA-256;
- typed source member SHA-256 and logical generation;
- route leg state IDs;
- core manifest and pointer hashes;
- route opportunity evidence bindings;
- complete manifest and atomic `routes/latest.json` pointer;
- cold reload validation after publication.

The public fee schedule bytes are read before calculation, their exact record
hash is included in every fee component, and the schedule is reread before the
complete pointer commit. A changed schedule aborts publication and preserves
the prior current pointer.

The command prints a receipt containing only schema/status, route cohort ID,
complete pointer identity, source venues, token pair, row counts, and optional
loopback URL. It never prints absolute paths, environment values, raw source
payloads, or exception bodies that may contain request data.

## Command interface

The manual entrypoint is:

```bash
python3 scripts/run_live_cex_opportunity.py \
  --data-dir /absolute/local/path
```

To start the existing normal Current Opportunity page after successful cold
reload:

```bash
python3 scripts/run_live_cex_opportunity.py \
  --data-dir /absolute/local/path \
  --serve \
  --port 8765
```

Arguments are limited to:

- `--data-dir`: required absolute local directory;
- `--public-fee-schedule`: optional absolute or repository-tracked schedule
  path, defaulting to `config/cex_public_fee_schedules.csv`;
- `--deadline-seconds`: optional integer from 10 through 60, default 60;
- `--serve`: serve only after publish and reload verification;
- `--port`: loopback port 1 through 65535, default 8765.

There is no token, venue, endpoint, direction, finalizer, profile, API-key,
host, or RPC argument.

## Failure behavior

The command exits nonzero and does not serve when:

- the data directory or fee schedule path is unsafe;
- the fixed universe does not reproduce its generation;
- either required book is not observed inside the bounded collection;
- typed market rules or USD conversion are missing;
- route timing exceeds the existing skew contract;
- raw or typed evidence changes during replay;
- fee schedule identity changes during finalization;
- the complete bundle cannot be cold reloaded;
- the loaded pointer differs from the pointer just published.

An individual notional that exceeds available returned book depth becomes an
unavailable scenario without invalidating other notionals. A failed refresh
does not overwrite the last valid complete pointer.

## UI behavior

The normal `/opportunities` page is used, not the sealed demo fixture page.
The result should visibly identify:

- `UNI` and `UNI/USDT`;
- Binance and Bybit;
- buy and sell venue direction;
- requested notional and common UNI quantity;
- gross buy cost, gross sell proceeds, gross edge;
- public bounded fee cost and research net edge when complete;
- research/unavailable classification and reason;
- source timestamps, age, skew, and freshness state.

No demo banner, fixture hash, or synthetic-token copy is shown for this path.

## Test and acceptance contract

Implementation is complete only when all of these pass:

1. Unit tests prove the fixed universe contains exactly the two venues, two
   directions, five notionals, and a reproducible generation.
2. Mocked public responses run through the real collector, typed-source
   attachment, quantity calculation, cost classification, complete publisher,
   cold loader, and API projection.
3. Mutating a book, rule member, fee schedule row, core pointer, or complete
   pointer is rejected without replacing the previous current pointer.
4. Missing/stale/ambiguous fee bounds never become zero and never yield an
   executable candidate.
5. Every successful public research result has strict fields forced false/null
   as defined above.
6. The existing authenticated finalizer, DEX research finalizer, current API,
   dashboard, publication, and release-smoke regressions pass.
7. One manually authorized real network run retains non-fixture raw bytes from
   both venues and publishes a cold-reloadable complete bundle.
8. A local HTTP check of `/api/markets/opportunities` returns the new cohort,
   and `/opportunities` renders it through the normal UI while fresh.
9. After the 120-second age boundary, the API projects the row stale or
   unavailable according to the existing freshness contract instead of
   continuing to advertise current economics.

The real network run and local HTTP check are acceptance evidence, not unit
tests. Tests never contact public hosts.

## Delivery order

1. Add the fixed research universe and TDD contract.
2. Add the separate public-research input builder and its fail-closed tests.
3. Add the one-command collector/publisher/server orchestration and tests.
4. Add reviewed public fee bounds only after official source verification.
5. Run focused and regression tests.
6. Run one real bounded collection, verify the normal API/UI, then publish the
   verified commits.

Automatic refresh and CEX-DEX support are separate increments because neither
is required to prove this first real-data Opportunity loop.
